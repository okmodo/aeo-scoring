The public Worker constructs the existing guard only with valid pinned account and subscription identifiers and its D1 binding. The guard reads active persisted evidence for that scope and checks freshness, period, all usage metrics, ceilings and receipt generation before reservation. Missing, wrong-scope or stale evidence denies admission; exhausted allowance returns 429. The public-entry SQLite regression exercises authenticated submission and polling through those cases and confirms denied submissions do not reach audit persistence. Its successful polling case uses a deliberately synthetic active receipt; it is not evidence that a real account has an authoritative receipt. Earlier review requested submission-path coverage and correction of a stale policy statement; the follow-up addresses both.

The Worker receives identifiers, not the collector's billing token. The shared CPU configuration remains 1,000 ms, the per-invocation reservation remains 2,000 ms, and the 60% ceilings are unchanged. The current collector cannot activate a production receipt. Trusted, sufficiently fresh account-wide evidence for every metric, competing usage, D1 and storage cost bounds, ingress and denied-request costs, and D1 runtime verification remain prerequisites before rollout. Inbound requests and admission queries themselves consume resources, so this is not a guaranteed account-wide billing cap.
