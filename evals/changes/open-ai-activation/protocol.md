# Temporary native validation protocol

This worker is a private, temporary validation harness. Upload as an inactive version with CPU 1000 ms and strictly public outbound egress; invoke only its preview endpoint. Leave production traffic and cron configuration unchanged. Set `AUDIT_VALIDATION_EXPIRES_AT` to a future Unix epoch in milliseconds, at most one hour ahead (the operator uses 45 minutes). Missing, expired, or excessive expiry returns 404 before authentication or admission. Delete the inactive version after testing. Its bindings and credentials must match the project account, subscription, analytics guard, D1 and private Standard R2 bucket. Keep the bearer secret and responses private; the authenticated response contains retained source material and provider output. Never log credentials or source material. Preserve the existing bucket lifecycle. Native CPU must be measured from platform telemetry, not inferred from this response.

The only requests are authenticated POST `/control` with `{"caseId":"control"}` and POST `/validate` with `{"caseId":"native-known"}`, `{"caseId":"synthetic"}` or `{"caseId":"kokatat"}`. The targets and synthetic HTML are fixed. A persistent analytics-backed infrastructure reservation per run ID and case rejects duplicates, including after failure. Each request has a 25-second assessment deadline, a 40-call cap and a bounded provider trace. R2 operations use the production R2 allowance; real model stages use the unchanged production analytics allowance and retain unknown usage. Known simulated stages use a bounded in-memory guard and record no actual provider usage. Reservations with uncertain outcomes must not be assumed settled.

Run control first, then native-known. Require successful settlement, assessed status, zero provider calls, retained profile and facts, exact input preservation, equal replay report and profile, changed-input rejection and no replay AI calls. Its cautious judgments exercise decoding and persistence; they do not establish scoring quality. Stop on failure or CPU limit. Only then run the fixed synthetic provider case once, if headroom allows. Stop on incomplete assessment, timeout, unavailable usage, admission failure or insufficient headroom. Optional Kokatat is a separate fixed one-shot case, only after acceptance and fresh headroom review. Independently review source-bound category, evidence and credit before activation. Provider output and source evidence are size bounded; missing or truncated evidence is not a pass. Do not retry uncertain calls.

The direct offline tests are `node --test evals/changes/open-ai-activation/runtime-worker.test.mjs`. Bundle this worker as standalone ESM with the project's compatible esbuild before deploying. Delete the inactive validation version after testing; retained objects follow their existing expiry and cleanup policy.
