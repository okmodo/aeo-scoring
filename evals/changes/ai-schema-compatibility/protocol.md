# R10 bounded validation protocol

No live calls or deployment are performed by this tooling. Before any inference, an independent reviewer must inspect the frozen runner requests, eligible and excluded evidence across all five cases, and the single required evidence-slot contract. Required source-bound checks and hosted CI must pass. Confirm ordinary account-wide allowance admission immediately before each call, and retain receipts. A failed phase is closed; do not retry or substitute outputs.

The fixed order is running-shoes, casual-daypacks, personal-flotation-devices, handbags, basic-tshirts. The normal shirt condition follow-up is allowed only if the runner requests it: at most six synthetic physical calls. Each case has a durable one-shot infrastructure claim and the normal AI allowance guard. The client first requires control CPU telemetry, records HTTP status before parsing, waits for primary CPU even after a failed response, and stops on any failure or absent/over-1000 ms primary CPU. Telemetry is reduced to request pathname and recognized root CPU milliseconds; raw provider request and output remain in the private proof for independent review.

Compare all 15 frozen findings for each applicable case and the unchanged shirt total 78.125 and pillar scores. Independent review must examine every raw slot assignment, empty slot, and unselected ID in nonempty slots against its exact original source and required references, separately from decoder/literal supplements; zero unsupported raw proposals are permitted. A matching grade alone is insufficient. Only after all five cases and their raw outputs pass independent review may one exact-input Kokatat validation occur, bringing the maximum to seven physical calls. Preserve incomplete/null score when evidence is incomplete. Verify actual settlement and cache without additional inference, and clean up temporary resources and credentials. This experiment does not authorize production activation.

Freeze with `node evals/changes/ai-schema-compatibility/freeze-inputs.mjs`; it reads the existing private R6 snapshot and writes a new private R10 real case and public synthetic cases and hash summary. Freeze only once against the independently reviewed final backend. Rebuild temporary single-module bundles with `node /private/tmp/aeo-r10-build.mjs`; hash them and bind the reviewed hashes to the deployment receipt. The real wrapper is the unchanged historical runtime-validation-worker, bundled against the current backend. Synthetic client uses `/private/tmp/aeo-ai-r10-synthetic-key.pem`, `/private/tmp/aeo-ai-r10-synthetic-envelope.json`, and `/private/tmp/aeo-ai-r10-synthetic-runtime.json`; real client uses distinct `aeo-ai-r10-real-*` paths. Both remove key and envelope after execution. The operator is responsible for creating unique secrets, envelopes, Tail sessions, bindings, and actual account receipts and for independently reviewing private proofs. Never commit private snapshots, credentials, or raw real-site content.

After each successful grade and CPU check, the synthetic client prints `awaitingReview` with the case ID and SHA-256 of the exact serialized result and pauses for up to 30 minutes. An independent reviewer must examine that private result and all raw slot assignments, unselected IDs, accepted facts, literal supplements, unknowns and absences against the source before the operator enters exactly `REVIEW_PASS <caseid> <caseResultSha256>` on the interactive terminal. The client records the gate decision in the private proof before proceeding. Wrong input, EOF, timeout or failed review closes the phase; do not resume or retry. No approval means no subsequent provider call.

Provider error name, code and bounded message are retained only in the private validation proof. Never copy a raw provider message into a public artifact. Preserve any unresolved AI reservation until actual usage is verified; the existing R9 hold remains in admission accounting.
