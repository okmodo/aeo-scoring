# Provider schema compatibility

R10 retains R9's direct evidence-slot semantics and strict decoding while removing `uniqueItems` from the provider-facing JSON schema. Duplicate IDs still fail server-side, including the same ID with different repeated contexts. Required slots, allowed IDs, unknowns, absence protection, source scopes, repeated contexts and scoring references are unchanged. This removes a provider hint; it does not relax application acceptance.

R9's first provider invocation threw before any output or usage was returned. Its original harness retained only a generic provider error, so the cause is unconfirmed. The current [vLLM xgrammar adapter](https://github.com/vllm-project/vllm/blob/main/vllm/v1/structured_output/backend_xgrammar.py) flags array `uniqueItems` as unsupported. That supports a compatibility hypothesis; it does not establish which engine or error Cloudflare used. R9 remains closed-failed, and its unresolved 1,004-neuron reservation stays held. No usage is refunded without verified consumption evidence.

The new private validation harness retains bounded provider error name, code and message for diagnosis if another call fails. These fields are limited to private proof files; production errors remain generic and public artifacts contain only reviewed summaries. Historical proofs are not modified or reclassified.

Independent review checks source and exact requests before calls, and every actual raw slot and omission after each category before continuation. No failedcase retries or replacement outputs are allowed. Current account admission includes the existing unknown hold; 60% ceilings, CPU1000 and the normal model timeout remain unchanged. Temporary resources and credentials are cleaned up; production activation, frontend, dependencies, access settings and unrelated services remain outside this change.
