# Phase 2 Cloudflare feasibility — research, 2026-11-05

**Decision: partial go for basic integration; no-go for an automatic judge or a CPU feasibility claim.** The user confirmed Workers Free. Two bounded synthetic model calls and one inline synthetic browser call have since been run; see [live experiment](cloudflare-live-experiment.md). One model result followed an injected instruction and failed the expected judgment. Account-wide remaining capacity and Worker CPU remain unknown. The intended application must assess evidence on representative pages and compare judgments with human scores; the numbers below are service allowances, not observed application performance.

The connected Cloudflare account listing returned one account. Read-only Workers account settings returned `default_usage_model: standard`; this is not proof of Free or Paid. A read-only subscription request failed with HTTP 403 because the connector lacks billing permission. The Cloudflare CLI was unauthenticated. A guessed Browser Run limits GET returned 404 and is not an authoritative usage check. No cloud resource, deployment, or settings mutation was performed; subsequent bounded model and browser calls are documented separately. Confirm the Workers subscription in **Manage Account → Billing → Subscriptions**, then check shared usage in **AI → Workers AI** and **Compute → Browser Run** immediately before a test. The connected account may have other consumers; yesterday's usage or a locally tracked budget cannot establish remaining capacity or reserve it against concurrent usage. [Billing dashboard](https://developers.cloudflare.com/billing/understand/how-billing-works/), [AI pricing and dashboard](https://developers.cloudflare.com/workers-ai/platform/pricing/), [Browser pricing and dashboard](https://developers.cloudflare.com/browser-run/pricing/).

## Published free limits and constraints

- Workers Free: 100,000 requests/day and 10 ms CPU per HTTP invocation; CPU excludes waiting for network requests. This is not a measurement of the scorer's parsing CPU, which must be measured. Free subrequests are limited to 50 external and 1,000 Cloudflare service subrequests per invocation. [Workers limits](https://developers.cloudflare.com/workers/platform/limits/), [subrequest clarification](https://developers.cloudflare.com/changelog/post/2026-02-11-subrequests-limit/).
- Workflows Free: 3,000 steps/day, 1 GB-month storage, 10 ms CPU per invocation, and requests shared with Workers. Check current billing details before use. [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/).
- Browser Run Free: 10 browser-minutes/day, three concurrent browsers; on Paid, excess duration can incur charges. REST `/markdown` is a plausible targeted fallback when raw HTTP extraction fails, not a default for every page. [Browser Run pricing](https://developers.cloudflare.com/browser-run/pricing/), [markdown endpoint](https://developers.cloudflare.com/browser-run/quick-actions/markdown-endpoint/).
- Workers AI Free: 10,000 neurons/day shared account-wide, reset 00:00 UTC; free plan operations fail when allowance is exhausted. Paid plan receives the same free allocation, then incurs charges. [Workers AI pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/).

## Candidate judge and bounds

`@cf/meta/llama-3.3-70b-instruct-fp8-fast` is a reasonable evaluation candidate, not an established best judge. Cloudflare documents a 24,000-token context and lists the model as supporting JSON Schema mode. Rates are 26,668 neurons/million input tokens and 204,805 neurons/million output tokens. The illustrative maximum of 2,000 total input tokens (including instructions and schema) and 512 output tokens yields 53.336 + 104.86016 = **158.19616 neurons** for one request, subject to actual billed token accounting. Two such calls would be about 316.4 neurons; this is an estimate, not an observed charge or account reservation. [Model](https://developers.cloudflare.com/workers-ai/models/llama-3.3-70b-instruct-fp8-fast/), [pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/).

Use a tokenizer or conservative verified bound for all prompt, message framing, and schema tokens before sending, and set `max_tokens: 512` after verifying current model request schema; skip the request if the 2,000 input-token limit cannot be established. Set a total two-request limit with no automatic retries, a 316.4-neuron estimated experiment ceiling plus explicit overhead margin, and independently record actual usage. These application bounds control this experiment only; they do not prevent other account usage or establish a platform-wide hard spending cap. JSON mode does not guarantee compliance; Cloudflare documents a possible `JSON Mode couldn't be met` error. Validate parsed data, allowed enum values, and every evidence reference locally; fail closed rather than using malformed or unsupported results. [JSON mode](https://developers.cloudflare.com/workers-ai/features/json-mode/).

## Minimal experiment after plan and budget confirmation

1. Confirm Free subscription and sufficient capacity in both product dashboards; pause competing account activity or treat usage as uncertain. Capture aggregate pre-test usage only. Do not change plan or enable paid services.
2. Use two frozen, already permitted representative page/evidence fixtures with human-labeled expected judgments, including one ambiguous or missing-evidence case. First evaluate raw extraction locally, then make at most two sequential JSON-schema model calls total with the above strict limits, no retries, and compare model evidence citations and decisions with labels. Record response/error, tokens, and elapsed time without private content or credentials.
3. For only one selected page where raw extraction demonstrably misses required client-rendered evidence, issue at most one Browser Run `/markdown` request, with a bounded navigation timeout supported by its current API schema, no retries and no additional crawls. Record actual duration and compare rendered versus raw evidence. A client timeout is not proof a remote browser stopped; verify usage afterwards.
4. Check aggregate post-test usage, quantify observed extraction, agreement and browser duration, and separately measure Worker CPU in an authorized deployment/test setup before claiming free-tier feasibility. Stop on errors, uncertain budget, excess usage or unexpected account state. The sample tests integration, not statistical judge reliability.

## API discovery

The connector exposes OpenAPI search and a JavaScript executor. Search found read-only `GET /accounts/{account_id}/workers/account-settings`, `GET /accounts/{account_id}/ai/models/search`, and `GET /accounts/{account_id}/ai/models/schema?model=...`. The documented inference endpoint is `POST /accounts/{account_id}/ai/run/@cf/meta/llama-3.3-70b-instruct-fp8-fast`; the Browser Run endpoint is `POST /accounts/{account_id}/browser-rendering/markdown`. These POST operations consume resources; they were invoked only in the subsequent bounded experiment described above. Dashboard usage is the verified monitoring path; no verified neuron-usage or browser-usage API endpoint was established in this investigation. Do not infer a safe remaining budget from account settings.
