## Algorithm and source preservation

The backend builds eligible observation IDs separately for each fact kind/key. The response schema binds a fact to that pair's eligible IDs, and the payload exposes the same compact candidate table. The decoder independently validates the actual request, source IDs, scopes, roles and context even if a provider ignores its schema. Empty candidate sets remain empty/unknown. Every original observation and completeness marker remains available for source inspection; excluding a candidate never establishes absence.

Eligibility is a conservative filter, not semantic proof. Before outputs, an independent reviewer checks both included and excluded observations against all frozen expected facts and the actual source.
