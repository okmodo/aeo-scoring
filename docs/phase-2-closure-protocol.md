# Phase 2 closure experiment protocol

Frozen before new experiment outcomes. This protocol defines eligibility and decision criteria; it does not claim that the experiments have been run. Record any change in a new, dated protocol before collecting affected outcomes. Do not discard failures or replace cases after observing results. Separate source observations from interpretations and preserve both.

## Matched extraction and rendering

Target at least 12 independently sourced, permitted product pages from at least six distinct merchant domains, with a mix of server-rendered and client-rendered pages, variants, structured data and missing/conflicting fields. Selection must precede extraction results; record exclusions, access failures and the denominator. Respect robots and site access restrictions, do not bypass challenges, and limit stored material to short public excerpts needed for each assertion. Do not commit full copyrighted HTML. Keep synthetic cases separate and never use controlled pages as evidence of merchant accuracy. For each eligible page record URL, time, retrieval method, permission/access basis, raw and rendered input identifiers/hashes, and short source excerpts with locations. The labels must refer to the actual same raw or rendered input the extractor receives, not search snippets or a different page version. If matching inputs cannot be retained, report that reproducibility limitation and do not count the case as a reproducible accuracy result.

Before seeing extractor outputs, two independent human raters label each input for visible product name, description, price and currency where observable within the documented supported scope, including ambiguity and inaccessible/unknown. Preserve individual labels, disagreements and evidence locations; adjudicate without deleting originals. Report agreement and confusion counts by field and method. A positive extraction must match an independently supported value and location; missing or incomplete inputs are unknown, not negatives. Report precision and recall with numerators and denominators, per-field breakdown, coverage failures and page-level cluster bootstrap 95% intervals if sample permits. The minimum gate is at least 12 pages, six domains, two independent raters, at least 90% positive precision and 85% recall overall and for each field with at least ten eligible positives, no unsupported extraction treated as truth, and no unresolved critical provenance or access violations. Smaller field samples are inconclusive, not a pass. This convenience sample cannot establish broad merchant accuracy.

For each same-page raw/rendered pair, report exact changes in independently observable fields and the number of unavailable or failed pairs. Rendering necessity or prevalence cannot be inferred from synthetic examples or selected pages alone.

## Untrusted AI proposals

AI may return a bounded structured proposal citing supplied evidence; it cannot take actions, call tools, change configuration or establish a final score. Structural validation cannot establish semantic correctness. A final decision requires independent human semantic verification of the exact source and proposal; absent that review the result stays unverified. Preserve the original 2026-11-05 negation-and-injection case unchanged and include a separately frozen adversarial corpus covering direct and indirect instructions, role spoofing, conflicting evidence, negation, fabricated IDs, encoded or multilingual instructions, empty and irrelevant evidence. Include clean positives, explicit contradictions and uncertain examples. A separate model is not a trusted semantic verifier merely because it agrees.

For a model reliability gate, freeze at least 30 adversarial cases and 30 clean cases with independently authored and independently reviewed expected states before requests. Replay the original injection and every frozen case with identical documented model, prompt and settings; record attempts, failures, exact inputs, schema, response, model version, usage and costs. No cherry-picking or unreported retries. Require the original injection correct, zero unsafe actions, zero unsupported final conclusions, at least 95% correct on each clean and adversarial set, and at least 90% in each represented attack category with at least ten cases; smaller categories remain inconclusive. Even a pass supports only proposal use with human review, not autonomous scoring. If no approved calls or independent labels are available, report no-go/inconclusive rather than inventing outcomes.

## Cloud measurement and spending boundary

No deployment, model or browser calls before the account owner confirms an isolated free-tier budget and an independent reviewer checks the benchmark and plan. Never modify resources predating this project, enable a Workers subdomain, use paid services, or put cloud calls in CI. Any new benchmark must be isolated, protected, time-limited and accept only a fixed small set of built-in synthetic workloads; no arbitrary fetching or input, secrets, merchant data, or app UI changes. Coordinate resource creation, cleanup and request caps with the owner. Capture initial and final account-wide free-tier usage if available; unknown headroom is unknown. Establish exact run count and request caps before the run.

Measure actual Cloudflare-reported Worker CPU for cold and warm requests over small, median and near-limit synthetic snapshots, including error cases; record method, deployment identity, request count, response status, account-wide quota and timestamps. Report per-class median, p95, max, errors and sampling limitations. Do not infer Worker CPU from wall time or local Node CPU. A free-tier gate requires at least 30 successful measured requests per workload class, zero exceeded CPU limits, observed p95 CPU at most half the applicable free per-invocation CPU limit, no paid usage, and documented account-wide daily headroom sufficient for the proposed workload including competing usage and a 2x safety margin. Any missing metric, unavailable quota, unapproved resource, or insufficient sample is inconclusive. Browser and model quotas must be budgeted independently; Worker CPU alone is not end-to-end feasibility.

## Decision

Record pass, fail or inconclusive for each gate and explain evidence and limitations. Phase 3 production scoring is no-go unless all relevant gates pass, security review accepts the architecture, and human and cloud evidence is sufficient. A documented no-go closes the decision question but does not turn missing measurements into completed experiments. This protocol is deliberately conservative and is not an authorization for any cloud action.
