# Direct evidence slots

R9 removes the duplicated decision strings and fact list that caused the R8 model response to fail despite correct literal fit and width findings. R6, R7 and R8 remain closed-failed in their original records. This is a separately planned representation change, not a retry or a reclassification of any failed output.

The model assigns source observation IDs directly to required role slots. Every eligible role has an explicit identifier and definition. An empty slot means unknown; it does not establish rejection or absence. A source can support several roles, and each role can retain multiple distinct observations. Repeated facts preserve their source-specific comparison context. The decoder validates the exact role set, allowed observation IDs, duplicates, shape, scope and context, then mechanically maps those assignments to the existing internal fact representation. This mapping does not invent semantic support, repair an invalid response or infer missing assignments.

The explicit width guard, source-preserving candidates, broad absence-prevention cues, scope completeness, safety and condition checks remain. The normal AI runner requires the new slots; historical low-level decoder compatibility is not a live bypass. The model, 60 KiB input, 32 KiB response and 2,048-token ceiling are unchanged; each model call reserves its bound using the ordinary account guard before inference. Actual completeness, latency and CPU require live evidence.

`evals/changes/evidence-slot-extraction/` contains the separately committed plan, exact frozen actual runner requests, unchanged source reference outcomes, protocol, independent review and handoff. The fixed order covers shoes, daypacks, PFDs, handbags and shirts. The client pauses after each passing result for an independent source review tied to that result's hash before any next provider invocation. A failure closes the phase with no retry or replacement. At most seven physical invocations cover the five primaries, normal optional shirt condition follow-up, then one exact-input Kokatat case only after all five pass independent review. Unknowns and omitted evidence are reviewed as well as selected raw slots, decoder facts and literal supplements.

Production AI stays off during this change. The frontend, dependencies, preview access, unrelated services, 60% operating allowances and 1,000 ms CPU cap are untouched. Temporary validation uses the production compatibility settings and ephemeral primary CPU telemetry; temporary Workers, Tail sessions and private credentials are removed after testing. Missing applicable evidence continues to yield an incomplete assessment with no final score. A schema or transport success alone does not establish evidence accuracy or release readiness.
