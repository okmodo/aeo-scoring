# Source-bound content facts and runtime validation

This draft describes the experimental content-fact path for the scoring engine. It is **not calibrated for production**: `CONTENT_FACTS_CALIBRATION_APPROVED` is false, and an AI binding does not override that gate. Failed, unsupported, unsafe or unavailable assessments leave unresolved checks unmeasured. A final score requires every applicable check to be measured. The earlier free-form semantic assessment remains a legacy offline fixture path; see [the prior engine record](complete-scoring-engine.md) for its calibration history.

The backend prepares a bounded, category-specific request from retained product and inspected policy observations. Each observation has a source URL, location and canonical sentence or line. The model proposes facts by kind, key and observation ID, and may propose explicitly inspected absences. It supplies neither quotations nor credit fractions. Narrow literal source patterns can also add explicitly identified facts independent of model proposals. The server derives the fact text from the cited observation, validates JSON shape, IDs and source scopes, and checks simple role, selected-context and cue constraints. A plausible role is not proof of semantic correctness. Missing inspections, failed or truncated retrieval, ambiguous roles, and unsupported representations stay unknown. Absence proposals are downgraded when the complete relevant scope is unavailable or a registered cue conflicts; the cue registry is a safeguard, not proof of exhaustive absence.

`backend/fact-grading.mjs` applies versioned category attributes and decision questions to validated proposals, computes C1–C5 fractions, and retains per-attribute, question, policy and comparison evidence. It distinguishes useful partial values from vague values, keeps contradictory shopper-visible values in consistency rather than reducing attribute completeness, and requires relevant evidence for material claims. The grader conservatively withholds judgments where it cannot establish scope or interpret a representation. Product-page and schema comparisons belong to S3. Sitemap usability requires completed relevant coverage; an observed exact inclusion remains an independent positive finding.

The frozen shirt source, policy evidence and source-reference response exercise the complete offline path without supplying model scores. The unchanged independently adjudicated result is **78.125** (Structure 20, Content 58.125), including partial decision support for a regular-fit label without an explanation of the cut. This synthetic result demonstrates that the application and fixture reconcile; it is not evidence that the model can extract facts reliably from merchant pages. `node --test backend/content-facts.test.mjs backend/fact-grading.test.mjs` covers source validation, unknown roles, negation, partial attributes, comparisons and the full fixture.

The current experiment pins `@cf/meta/llama-3.3-70b-instruct-fp8-fast`; the JSON-schema request is bounded to 60 KiB and 1,536 output tokens, and the decoder bounds responses to 32 KiB. The runner permits one call, reserves against the existing project daily budget before invoking the model, and retains reservations for errors and timeouts. The 20-second timeout does not cancel a provider call. Free-tier billing limits and existing authorization remain in force; do not infer remaining account headroom from a local estimate.

The isolated runtime test failed the Workers Free CPU target. All 11 requests returned successfully, and five background jobs emitted completion events, but CPU ranged from 7 to 418 ms against the documented 10 ms limit. The Kokatat retrieval/preparation route used 418 ms without inference or persistence. The temporary Worker was deleted; the existing services were unchanged. [Sanitized measurements](../evals/changes/content-facts-runtime/runtime-measurements.json) bind these results to the exact tested bundle. Later source changes have not been measured. [Local profiling](free-tier-parser-performance.md) identifies callback volume as a lead, without claiming CPU compliance. Workflows also impose a Free CPU limit; simply moving the same work into a background task does not solve this problem.

Policy source inspection now allows up to 1 MiB, with the existing optional and total deadlines. The earlier 128 KiB cap rejected a real 172,686-byte policy template before its terms could be assessed. Oversized or failed policy retrieval still stays unmeasured. This change needs final-source runtime validation alongside the rest of extraction.

A supplied synthetic model output was independently inspected and rejected by the current decoder. It used combined kind labels and unsupported inspection statuses and omitted required facts. Its SHA-256 is `c042bd1c44d7e821a2ef0ea704648cea6b136ff96fa2b590ce9708ca81f63300`; the raw capture is not committed. This failed observation does not establish a calibration rate. Representative independently adjudicated cases, including successful source-bound real-product reports, remain necessary before enabling the gate. Runtime bundle identity, actual Worker CPU and lifecycle observations, the current inference reservation ledger, hosted CI and independent final review must be recorded separately; ordinary offline tests do not establish them. No production deployment or release is implied.
