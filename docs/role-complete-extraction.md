# Role-complete AI extraction

R8 corrects two independently observed R7 failures: omitted product-specific shoe fit and a fit sentence proposed as explicit width. It does not reclassify or retry the closed R6/R7 experiments.

The AI request now includes a required decision string for every eligible role. Each character corresponds to one source observation in that role's ordered candidate list: S means supported, N means unsupported, and U means unknown. Each S must correspond to exactly one raw fact proposal; omitted, extra, duplicate or inconsistent decisions fail decoding. A source may support multiple distinct roles, and all such roles are assessed separately. Unknown never proves absence. Facts retain individual observations and repeated comparison contexts.

Width eligibility and decoding require actual width evidence. Broad absence-prevention cues remain intact; rejecting a fit-only sentence as width does not remove that sentence or prove width absent. Product-specific fit, policy evidence, incomplete coverage, unsafe instructions and conditional checks keep their existing semantics. The normal runner requires the decision contract; historical low-level decoder compatibility does not bypass the live guard.

The existing 60 KiB input, 32 KiB output and 2,048-token runner ceiling remain. R8 requests use the existing output ceiling, and reservations account for it before inference. Byte-size measurements are not model token counts; schema compliance or complete output is not guaranteed. Partial or malformed responses fail closed. Cloudflare's [JSON mode documentation](https://developers.cloudflare.com/workers-ai/features/json-mode/) likewise requires application validation.

The separate R8 experiment freezes exact actual runner requests and unchanged reference outcomes before outputs. It tests the fixed five categories once, then one real Kokatat request only after all category outcomes and every raw source assignment pass independent review. There are at most seven provider invocations including the normal optional shirt condition follow-up. Historical failures, unsupported raw proposals and unsuccessful outcomes remain recorded; none are repaired into a pass by scoring supplements. The complete protocol and handoff are in `evals/changes/role-complete-extraction/`.

The 60% account limits, 1,000 ms CPU cap, existing preview access and production AI-off setting remain unchanged. Temporary validation uses the production compatibility date/flags for a meaningful comparison, disables persisted logs/traces under the project allowance policy, and uses ephemeral Tail CPU measurements. This change authorizes validation, not production activation. Missing applicable evidence still yields an incomplete assessment and no final score.
