The user approved this release work on November 11, 2026. This protocol governs the bounded first-public-version assessment release and is recorded before new model results. The earlier Phase 2 experiment protocol remains a historical research record. Its Free CPU target and research sample sizes are superseded for this release by the approved Workers Paid operating policy and this task-specific validation. This small cohort supports a provisional product release, with no claim of population-wide accuracy.

## Model and operating envelope

Use the existing pinned Cloudflare Workers AI model and source-facts schema with temperature zero. Models propose source IDs and fact roles. Server code assigns credit. Record prompt/request hashes, model, settings, attempts, output validity, usage and elapsed time. Maximum ten initial calls, one per eligible frozen case, and no automatic retries. Any prompt/schema revision needs a new protocol revision recorded before affected calls, with all failures retained.

Before each live call reserve conservative neurons through the existing account allowance ledger against the actual current UTC day and available analytics estimates. Total local reservations and observed account usage must remain below 6,000 neurons daily. Request and CPU reservations, D1 limits and stock limits also apply. Failed calls keep their reservations. Stop when admission fails. The Worker retains its 1,000 ms CPU setting, and model waits use the existing timeout and background lifecycle.

## Release gates

All frozen synthetic cases must exercise valid source-cited facts and the expected score/evidence outcomes without changing the existing adjudicated shirt total of 78.125. Adversarial and ambiguity regressions must preserve unknowns, exclusions, negation, selected context and rejection of fabricated citations. Every accepted proposed fact and absence judgment in this bounded cohort needs independent source review; unsupported proposals are a release failure and require correction and recorded revalidation. Inaccessible inputs remain explicitly unavailable.

Production activation additionally requires a successful real-product fact assessment, independent final code/evidence review, all source-bound evaluations and hosted CI, native-runtime replay, and actual Cloudflare runtime observations. Verify submission, status, report, cache, admission failures and retrieval failures through existing entry points. A valid incomplete report must identify specific unmeasured evidence. API success alone does not establish complete scoring or CPU compliance. Record sampled telemetry and missing measurements honestly. All mutations are limited to the project Worker and its existing database. The frontend and unrelated services stay outside this release.

Source-grounded size recognition corrects the omission, with the original raw output retained. Unknown condition judgments require another actual inspection before they can change.

It may return only the requested condition keys as absent or unknown. Apply the existing source-completeness and cue checks and independently review the raw follow-up proposals. Any unavailable, unsafe, timed-out, malformed or conflicting result preserves the original facts and unknowns.

An assessment's original atomic D1 reservation remains fully allocated and is never refunded. Before any focused call, privately allocate its entire conservative request/output bound from that assessment's unused reserved capacity.
