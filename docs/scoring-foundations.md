# Scoring foundations v1

The versioned [rubric](../config/rubric.v1.json) fixes 40 Structure and 60 Content points, criterion and subcheck allocations, anchors, evidence requirements and score limitations. Its linked sources support the underlying practices; the numerical allocations are editorial choices. The [category templates](category-templates.md) and [crawler policy](crawler-policy.md) provide the corresponding versioned pools. The vault's scoring contract remains the governing interpretation.

The offline reference harness accepts already assessed subcheck fractions. It does not extract pages, perform robots parsing, judge evidence, determine applicability, or implement a production audit. It validates the registries and demonstrates arithmetic with fixed synthetic inputs and independently specified expectations. The reference cases are neither live measurements nor human calibration. Run `npm run test:foundations`.

Full, half and zero are default anchors; averaged attribute, question, claim and crawler pools can yield other fractions. The harness requires all checks explicitly, rejects unsupported subcheck exclusions, preserves precision, redistributes justified excluded weight within a criterion and withholds the final score for unknown category (both C2 and C4 are unmeasured), unmeasured checks or an empty criterion. Earned points during incomplete assessment are provisional and must not be presented as a final score. The reference input's evidence strings are illustrative; real assessments must record quoted evidence or an absence check, location and retrieval method, plus the audit context specified in the rubric. For a conditional C4 group, the reference accepts exclusion only when every question in the selected template is conditional and has an exact matching condition and question ID with recorded evidence, location, and method establishing absence. Unknown conditions remain unmeasured. Production assessment still needs actual evidence inspection and category-level attribute applicability. The rubric also pins the project’s S2 schema-validation policy and its provenance requirements; this harness does not parse markup.
