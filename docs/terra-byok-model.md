# Terra through the existing Cloudflare BYOK endpoint

`config/ai-model.json` is the central configuration for the active rubric model: endpoint, gateway ID, API format, model, reasoning, response format, timeout, request/output byte bounds. The endpoint remains the user-supplied account `/ai/run` endpoint; the model is `openai/gpt-6.1-terra`.

The adapter sends `{model, input}` to that same endpoint with `cf-aig-gateway-id: openai`, explicitly selecting the existing gateway containing the stored default-alias OpenAI key. The earlier adapter omitted this header, and a controlled reproduction returned HTTP 402 / error 7007: no applicable provider credentials. The gateway ID and Responses API format are central configuration, rather than assumptions about account defaults.

Inside the envelope, the Responses payload maps the existing messages to `input`, reasoning to `reasoning: {effort: "low"}`, and JSON-object mode to `text: {format: {type: "json_object"}}`. Streaming remains disabled and sampling parameters are omitted. The response normalizer accepts completed assistant `output_text` content from the Responses result and rejects incomplete, refused, malformed or unsupported output. Requests omit the application’s per-stage generation caps. The provider’s own limits still apply, and the response stream is bounded in bytes. Prepared source batches use the serialized request byte budget, including instructions and envelope overhead. Checkpointed scoring no longer imposes its own model-call count or a separate intermediate observation size limit. The scoring rubric, evidence validation, report formats and pipeline stages remain unchanged. The user-started continuation dispatches one model step per RPC and stops on completion or failure. Platform invocation limits and retention still apply.

The production transport binds the default global fetch receiver and trims surrounding whitespace from the Cloudflare credential before constructing the bearer header. Injected test fetch functions remain untouched. Fetch exceptions expose only closed classifications such as illegal invocation, invalid header, I/O context or network; raw exception messages are excluded. The earlier adapter used `redirect: "error"`, which Workers rejects while constructing the request. The corrected adapter uses `manual` and rejects redirects without following them or forwarding the credential to another host. A native Worker regression verifies this boundary; binding/token normalization are additional hardening, not a substitute for that runtime test.

The existing Gateway BYOK default provider key supplies the OpenAI credential. The Worker does not need that OpenAI key. Before deployment, the project Worker needs a Cloudflare authentication secret named `AUDIT_AI_GATEWAY_TOKEN`, scoped to this account with Workers AI Read permission. Billing/Analytics/R2-only credentials cannot authenticate inference. This PR does not write or alter any secrets or Gateway settings.

`cf-aig-no-wholesale: true` prevents fallback to Cloudflare Unified Billing when the stored provider credential is unavailable. `cf-aig-max-attempts: 1` requests a single attempt. There are no application retries or provider fallbacks. A single 30,000 ms timer in the rubric caller aborts the HTTP request. Network, provider-envelope, refusal, truncation, invalid JSON and bounded-body errors fail closed. Internal diagnostics contain only bounded allowlisted phase/status/error-code metadata; provider bodies, messages, prompts and credentials must never enter logs or public report responses.

BYOK inference is billed to the configured OpenAI account, rather than Workers AI neurons. The model caller therefore no longer reserves or settles Workers AI neurons or estimates Llama usage for these calls. Existing infrastructure admission, 60% operating limits, legacy uncertain reservations, 1,000 ms Worker CPU cap, retention, and user-started-only behavior remain unchanged. This change adds no external-provider spending meter. Checkpoint digests include the configured model/settings so incompatible existing outputs cannot silently replay; older audits are not migrated.

Offline tests exercise the actual transport with frozen synthetic HTTP responses, existing rubric fixtures, SQLite/R2 roundtrips, aborts, failures, and checkpoint replay. A fresh agent resumes an exported checkpoint without reissuing the completed HTTP request. These tests do not establish live credential readiness, endpoint compatibility, latency, scoring quality, or provider charges. Ordinary CI makes no live calls. User-authorized operator diagnostics and rollout remain separate from offline checks and retain the existing 60% admission guard. They do not change provider credentials, billing settings, frontend files or dependencies. A provider 429 must not trigger retries, alternate models, or Cloudflare billing fallback. The configured 1,000 ms cap is preserved; deployment validation must report actual CPU telemetry rather than assuming an exact runtime cutoff.

A guarded provider-native diagnostic against the same gateway/default key exposed `insufficient_quota` / `credit_balance_exhausted` behind the generic `/ai/run` 429. This does not authorize buying credits or changing billing. The gateway and payload fixes can be deployed independently, but successful real-page AI validation needs available provider credits. See `evals/changes/terra-gateway-payload/upstream-investigation.json` for the route and credential limitations.
